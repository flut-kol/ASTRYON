## Per-source attributes to collect (questionnaire)
For each concrete source the owner fills, and it is recorded in `sources` (PostgreSQL) + this catalog:

1. Owner, tenant, environment, contact.
2. Delivery SLA: max acceptable ack latency, freshness (time to queryable), completeness expectation.
3. Format, schema owner, schema evolution policy, expected `schema_id/version`.
4. Rate: average, peak, burst duration; per-event and per-batch/file size (p50/p95/max).
5. Ordering need (entity_key), duplicate behaviour (does the source retry with the same `event_id`?), late/out-of-order arrival window.
6. Retention/legal: hot retention, archive in S3, deletion/erasure requirements.
7. Security: authN method (AAS token, see `authentication.md`), PII fields and masking/tokenization needs, network zone, secret handling (secret references only).
8. Whether CDC, batch ETL or OCR is required, and the replay requirement.

## Security notes
- `tenant_id` is taken only from validated token claims, never from headers/body.
- Source credentials are stored as secret references only; large objects only in controlled S3 buckets (SSRF controls for connectors, §12).
- PII is masked in logs; sensitive fields flagged per source.
