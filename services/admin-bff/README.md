# admin-bff

Backend-for-frontend for the Admin UI (`docs/architecture/authentication.md`, flow "Admin UI"). AAS is the only IdP.

- `GET /auth/login` -> redirect to AAS (Authorization Code, PKCE S256, `state`, `nonce`; pending state is single use, bound to a short-lived login cookie).
- `GET /auth/callback` -> checks state cookie, exchanges the code (client auth: `private_key_jwt` ES256 via `BFF_CLIENT_KEY_FILE`, or `BFF_CLIENT_SECRET` for dev only), checks the ID token (issuer, audience, expiry, nonce; received straight from the token endpoint over TLS), creates a server-side session. Only an opaque id reaches the browser: `__Host-astryon_session`, `HttpOnly; Secure; SameSite=Lax`.
- `GET /auth/me` -> `{authenticated, subject, session_expires_at}`; never returns tokens.
- `POST /auth/logout` -> drops the session, returns `logout_url` (AAS end_session with `id_token_hint`) for the browser to follow.
- `/api/<service>/...` -> reverse proxy to `BFF_UPSTREAMS`; the browser's `Cookie` and `Authorization` are dropped and `Authorization: Bearer <access token>` is added; the token is refreshed (refresh_token grant, under a per-session lock) when it has under 30 s left, otherwise the session ends with 401 `session_expired`. The tenant is never set here: it stays a claim in the token.
- CSRF: unsafe methods need `X-Requested-With: astryon-admin` and, if sent, `Origin` equal to `BFF_PUBLIC_ORIGIN`.

Env: see `cmd/admin-bff/main.go`. Register `BFF_PUBLIC_ORIGIN + /auth/callback` as the exact redirect URI of client `astryon-portal`.

- `POST /auth/backchannel-logout` (OIDC Back-Channel Logout 1.0, called by AAS, no cookie): the `logout_token` form field is verified against the AAS `jwks_uri` from discovery (RS256/ES256 only; unknown `kid` refetches the JWKS at most once per 10 s), `iss` = discovery issuer, `aud` contains the client id, `iat` within 5 min (1 min skew), `exp` if present, `jti` required and single use (replay store, so also across replicas), `events` must hold the back-channel-logout object, `nonce` must be absent, `sub` or `sid` required. Sessions with that `sid` (else all with that `sub`) are ended. Any rejection is a 400 `invalid_request` without detail. Register `BFF_PUBLIC_ORIGIN + /auth/backchannel-logout` as the client's back-channel logout URL (with `backchannel.logout.session.required` so AAS sends `sid`).
- Session store: in-memory by default (one replica; a restart signs everyone out). `BFF_REDIS_URL` (`redis://[:password@]host:port[/db]`, `rediss://` for TLS) switches login state, sessions, sid/sub indexes and logout `jti` marks to Redis so replicas can run behind any load balancer. Sessions hold access and refresh tokens, so they are sealed with AES-256-GCM using `BFF_SESSION_KEY` (base64, 32 random bytes, required with Redis, same on every replica; the key name is authenticated data); the URL and key come from the environment only. Keys expire with `BFF_SESSION_MAX_AGE`; `MaxSessions` is not enforced on Redis. The cookie is unchanged (opaque, HttpOnly). If Redis is down the BFF fails closed (signed out / 503). Redis client is a small stdlib RESP implementation (needs Redis >= 6.2 for GETDEL); no new Go dependencies.
- Tests: `go test -race ./...` (fake AAS); Redis integration tests run when `BFF_TEST_REDIS_URL=redis://127.0.0.1:6379/15` is set (e.g. `docker run --rm -p 127.0.0.1:6379:6379 redis:7-alpine`), otherwise they skip.

Not done: DPoP-bound tokens (rejected with 502), proxying WebSockets, Redis Sentinel/Cluster, cross-replica locking of token refresh (two replicas refreshing the same session in the same instant can race; the loser re-reads the winner's tokens, but a rotated refresh token may still end the session), `iss`/`sid` scoping of the session index for several issuers (one AAS realm assumed). Verified only against a fake AAS and a local Redis 7, not against real AAS (back-channel URL is not registered on `astryon-portal` yet).
